01asyncio · event loop · order book
Concurrent systems

Adaptive market-making simulator

A financial simulation engine that quotes both sides of a market while volatility shifts underneath it, built to test whether an adaptive spread beats a fixed one.

Problem

Market-making strategies look fine on calm data and blow up in stressed regimes. I wanted a harness that could replay volatility spikes and measure PnL variance honestly.

Approach

Python asyncio for non-blocking I/O task management, so order flow, quoting and risk checks run as concurrent tasks. Order book lookups use a sorted structure for O(log n) access.

Result

35.9% reduction in simulated PnL volatility across stress-tested market regimes, compared with the fixed-spread baseline.

02docker · aws · ci/cd
Distributed data

Event-processing platform

A distributed pipeline that ingests, validates and routes high-volume event streams, deployed on AWS with a CI/CD path from commit to container.

Problem

High-volume streams fail quietly: a malformed record slips through and corrupts everything downstream. Throughput and integrity usually fight each other.

Approach

Asyncio workers in Docker containers on AWS, with custom schema validation layers at the ingest boundary. CI/CD builds and ships each change automatically.

Result

Sustained 10,000 records per second with validation on, with data integrity held across concurrent streams.

03langchain · vector db · evals
Applied AI

RAG-based AI assistant

A retrieval-augmented generation assistant with an evaluation harness built in from the start, so every change to retrieval or prompting is measured, not eyeballed.

Problem

RAG demos answer confidently and wrongly. Without a test set and failure taxonomy you cannot tell whether a change helped.

Approach

LangChain pipeline over a vector database behind a REST API, with modular evaluation logic and structured failure-mode analysis across a fixed set of test queries.

Result

Measurably fewer hallucinated and irrelevant responses across the test query sets after each retrieval and prompt iteration.

04scikit-learn · anomaly detection
Machine learning

Credit card fraud detection

An anomaly-detection service that scores transactions in real time, tuned for the precision and recall trade-off that fraud teams actually live with.

Problem

Fraud is rare, so accuracy is meaningless. A model that flags nothing scores 99%. The real target is catching fraud without burying analysts in false alarms.

Approach

Feature engineering over transaction history, a scikit-learn anomaly-detection model, and precision/recall optimisation on held-out datasets, served through a REST API.

Result

Deployed scoring of high-risk transaction patterns in real time, with thresholds chosen from the held-out precision/recall curve.
